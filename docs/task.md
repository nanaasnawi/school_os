## A. Architecture Requirements (ARD)

### A.1 Technology Stack

| Layer | Teknologi | Versi |

| Mobile | Kotlin + Jetpack Compose | future |

### A.2 Architecture Principles

1. **Domain-Driven Design** — setiap domain independen, pakai Ubiquitous Language
2. **Clean Architecture** — dependency rule: Presentation → Application → Domain ← Infrastructure
3. **Event-Driven Architecture** — komunikasi antar domain via EventBus
4. **CQRS Ready** — pisah Command (POST/PATCH/DELETE) dan Query (GET)
5. **API First** — OpenAPI spec sebagai kontrak, frontend consume dari generated SDK
6. **Multi-Tenant** — satu backend untuk banyak sekolah, tenant_id wajib di setiap query
7. **Secure by Default** — JWT, RBAC, audit log, input validation
8. **Modular & Scalable** — tiap domain bisa dikembangkan parallel

### A.3 Dependency Rules

```
┌─────────────────────────────────────┐
│          Presentation               │
│   (api-server/src/presentation/)    │
│              │                      │
│              ▼                      │
│          Application                │
│   (school-core/*/application/)      │
│              │                      │
│              ▼                      │
│            Domain                   │
│   (school-core/*/domain/)           │
│              │                      │
│              ▼                      │
│        Infrastructure               │
│   (school-core/*/infrastructure/)   │
└─────────────────────────────────────┘
```

**YANG TIDAK BOLEH:**
- Domain → Presentasi (misal: `use axum::...` di domain)
- Infrastructure → Presentasi
- Application → Infrastructure (harus lewat DI / trait)

### A.5 API Contract

- Base path: `/api/v1/<resource>`
- Auth: JWT Bearer token (kecuali `/health`, `/auth/login`)
- Pagination: semua list endpoint pakai `Page<T>` response
- Error format: `ApiResponse<T>.error` berisi `ApiErrorDetail { code, message, details, trace_id }`
- OpenAPI spec: generate dari `main.rs` → `frontend/openapi.json` → SDK lewat `@hey-api/openapi-ts`
- Breaking changes: WAJIB buat version baru (`/api/v2/...`), jangan ubah response schema yang sudah ada

### A.6 Non-Functional Requirements (NFR)

| Kategori | Target |
|----------|--------|
| Availability | 99.9% uptime |
| Max Response Time (API) | < 200ms (p95) |
| Max Query Time | < 50ms |
| Concurrent Users | 10.000+ |
| Code Coverage | > 80% (unit), critical path covered (integration) |
| Memory Leak | Zero — wajib di-check dengan cargo test + valgrind/miri |
| Security | JWT + RBAC + audit log + input validation + argon2 |
| Scalability | Horizontal scaling via stateless backend |
