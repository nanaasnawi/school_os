# ADR-0005: UUID v7 untuk Primary Keys

**Status:** Accepted
**Date:** 2026-07-20

## Context

Semua primary key di database menggunakan UUID. Pemilihan format UUID penting karena mempengaruhi performa index di PostgreSQL.

## Decision

Menggunakan **UUID v7** (time-ordered) untuk semua primary key, bukan UUID v4 (random).

Alasan:
1. **Index Performance** — UUID v7 dihasilkan dari timestamp sehingga values berurutan → B-tree index lebih efisien
2. **No Auto-increment** — menghindari masalah migrasi, konflik, dan enumerasi ID
3. **Distributed-friendly** — bisa generate tanpa koordinasi (tidak perlu sequence)
4. **Inherent timestamp** — bisa mengekstrak waktu pembuatan dari ID tanpa kolom terpisah

## Consequences

- **Positive**: Performa index lebih baik dari UUID v4, sorted by default, no sequential leak
- **Negative**: Tidak bisa pakai `SERIAL` / `BIGSERIAL` — storage 16 bytes per key
- **Risk**: Collision secara teoritis mungkin — probabilitas sangat rendah (122 bit random)

## Compliance

- Semua entity: `pub id: Uuid` → inisialisasi dengan `Uuid::now_v7()`
- Di Rust: `uuid = { version = "1.8", features = ["v7"] }`
- Migrations: `id UUID PRIMARY KEY DEFAULT gen_random_uuid()` — aplikasi yang menentukan ID via `Uuid::now_v7()`
